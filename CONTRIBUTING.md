# Contributing to Scout

Thanks for improving Scout. Contributions should make career guidance easier to
understand, more accessible, or more grounded in evidence. Start with a small,
testable issue rather than a large unreviewed rewrite.

## Where to start

- **New to Scout?** Try the [browser demo](https://ruslanmv.com/scout/) and the
  [Quickstart](docs/QUICKSTART.md).
- **Bugs and features:** Open an issue with steps to reproduce, expected
  behavior and the relevant route. The [issue templates](.github/ISSUE_TEMPLATE/)
  help collect enough context.
- **Source data:** Include attribution, coverage, collection date and measurement
  units for new integrations. Never represent synthesized examples as hiring demand.
- **Documentation and accessibility:** Copy changes, cross-browser testing,
  contrast, keyboard and screen-reader fixes are welcome.

## Development setup

Scout requires Python 3.10+; Node.js is used for JavaScript syntax checks in CI.
From the repository root:

```bash
git clone https://github.com/ruslanmv/scout.git
cd scout
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m pip install -e ".[dev]"
python scripts/generate_snapshot.py
python -m pytest
node --check scout/scout-app.js
node --check scout/scout-landing.js
```

Run the local application with `python -m uvicorn app.main:app --reload`
then open `http://127.0.0.1:8000/scout/` or `/docs`.

## Site development

- Landing JSX source: `scout-landing.jsx`, with its precompiled counterpart
  `scout-landing.js`. React is vendored locally, not pulled from a CDN.
- Report pages: generated by `scripts/build_scout_site.py` from templates.
  **Modify the generator**, then regenerate and review `scout/report/`; do not
  change only a generated HTML file.
- Daily data: `scripts/build_pulse.py` and related collectors. Keep all
  historical observations source-labeled and never publish secrets.
- Static bundle: `python scripts/export_for_github_pages.py` generates
  `public/`. The branch-based site publishes the contents of `scout/`,
  *not* `public/scout/` at a nested `/scout/scout/` path.

For site changes, keep the matching `scout/` and `public/scout/` assets in
sync where already committed. Run relevant tests and check responsive behavior.

## Submitting a pull request

1. Create a topic branch and make a focused change.
2. Add or update regression tests for bugs. For UI fixes include a before/after
   screenshot or a testable description; screenshots must avoid personal data.
3. Run `python -m pytest` and affected JavaScript checks.
4. Link the issue, describe the user impact, data provenance and any limits
   (especially when recommendations are curated rather than verified).
5. Check that generated assets, links and README dynamic trends markers are
   preserved. The section between `SCOUT:TRENDS:START` and
   `SCOUT:TRENDS:END` is regenerated by a scheduled workflow—do not edit it
   by hand.

## Safety and data integrity

Do not commit API keys, tokens, private health data, confidential resumes,
location coordinates, or copyrighted datasets without redistribution rights.
For regulated professions, provide general career guidance rather than
suggesting users carry out unsupervised professional work. If a source is
missing, display that limitation instead of inventing data.
